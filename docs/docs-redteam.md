# Red team: the docs consistency spec (2026-10-18)

Reviewed: [docs-spec.md](docs-spec.md) and avd-swarm spec §6e at the commits that add them. Each finding has a severity, what goes wrong, and the change to the spec. **Status** says whether the spec now reflects it.

Severity: **C** critical (a leak or a path around review), **H** high (a guarantee the spec makes but can't keep), **M** medium (a gap that will cost a cycle), **L** low.

## Findings

| # | Sev | Finding | Change | Status |
|---|---|---|---|---|
| W1 | C | **A GitHub wiki bypasses review.** A wiki is a separate git repo: anyone with write access edits it, no PR, no CI, no guards. An agent with wiki access could rewrite "how to approve a plan" with nobody reviewing it, and agents would then cite it. | The wiki is generated Markdown in `wiki/`, changed only by a draft PR a person merges. A public repo's GitHub wiki, if ever used, is a one-way mirror overwritten on each publish with a "generated, don't edit" banner, and agents never read it. | Fixed in spec §3, §7 |
| W2 | C | **Generated docs can leak.** The generator reads code and comments; a test fixture, an example or a comment can hold a tenant or subscription ID, and the wiki, now public, aggregates every repo's text in one place. | D11 runs the sensitive-data guard and `check-no-ids.sh` on every generated file and on the findings file, as an error that is never downgraded. The sweep reads only `sources/sources.json` repos; tenant-swarm, vaults and private evidence are never sources. | Fixed in spec §3, §6, §9 |
| W3 | H | **A shared check is a supply-chain path into every repo's CI.** (Revised 2026-10-18 when this repo went public. The first draft assumed it stayed private, where public repos can't call its workflows at all.) If callers use `@main`, whoever can merge here changes what runs in five repos, and a quietly loosened check passes their PRs. | Callers pin the reusable workflow to a commit SHA and grant it `contents: read` only; bumping the pin is a reviewed PR in each caller. `.github/workflows/` here is a protected path with CODEOWNERS review, and Scribe can't touch it (W5). | Fixed in spec §7 |
| W4 | H | **A model writing docs invents facts.** A changelog line or README paragraph drafted by a model can state a parameter or behavior that doesn't exist, and a reviewer skimming docs PRs will merge it. | Generated text (reference, tables, changelog) comes from the generator, not a model. A model drafts only prose, and every draft PR must pass the same deterministic check. The judge only flags, a person confirms a judge finding before Scribe acts on it, and the judge is audited with seeded faults. | Fixed in spec §8, avd-swarm §6e |
| W5 | H | **Docs are instructions to agents.** `CLAUDE.md`, skills and agent prompts are read as rules. If Scribe can edit them, a poisoned comment or PR body that Scribe reads can rewrite the rules other agents follow. | `CLAUDE.md`, `.claude/`, agent prompts, `governance/`, workflows, `LICENSE`, the project notice, and here `knowledge/` and the facts of record are protected paths for Scribe; default branches are protected so its App can't push to them: a PR it authored that touches them fails CI. Code comments, PR bodies and doc text are untrusted input to Scribe, as conversations are to Improve. | Fixed in spec §10, avd-swarm §6e |
| W6 | H | **Which side is wrong?** Without a rule, a finding "README says X, code says Y" gets fixed by whichever side is easier, and code can be bent to match a stale doc. | Sources of truth (spec §4): code wins on behavior, the brain's facts of record win on cross-repo facts, decisions win on intent. Each finding names the side to fix. Scribe never changes code to match docs. | Fixed in spec §4, avd-swarm §6e |
| W7 | M | **Scribe floods repos with PRs.** A first sweep across five repos could find hundreds of issues and open as many PRs, burying real work and burning tokens. | At most one open Scribe PR per repo, batched by check; generated fixes first; the daily token cap from avd-swarm governance applies. | Fixed in avd-swarm §6e |
| W8 | M | **Day-one backlog blocks everyone.** Turning the checks on as errors fails every unrelated PR until the backlog is cleared. | Two weeks as warnings; then errors for the checks the backlog has cleared. | Fixed in spec §6 |
| W9 | M | **Paired PRs drift between sweeps.** One side of a pair can merge while the other sits open, and the decisions disagree until the next sweep. | Now that every connected repo is public, the PR-time check confirms that the linked pair PR exists, using the read-only token; D5 compares the paired decisions in the nightly sweep. | Fixed in spec §6 (D5) |
| W10 | M | **The check is checked against moving targets.** Sweeping each repo's `main` at different moments gives findings that disappear on rerun. | The sweep reads the commits in `.sources/lock.json`, and C13 records them; a finding cites the commit. | Fixed in spec §9 |
| W11 | M | **The changelog depends on a PR body convention people forget.** | D6 starts as a warning; Scribe proposes the missing line from the merged diff, and the PR template in each repo gains a `Changelog:` line. | Fixed in spec §6, §12 |
| W12 | L | **Terms checks are noisy.** Code, quotations and other vendors' product names will trip D8. | D8 skips code blocks and quotations, and stays a warning. | Fixed in spec §6 |
| W13 | L | **Actions cost.** | None: every connected repo is public, so Actions minutes are free (revised 2026-10-18). | Fixed in spec §11 |

## What held up
- The deterministic check needs no model, no Azure resource and no new identity, so D0 is safe to build first and cheap to throw away.
- The split follows decision 0003 without exceptions: the brain decides what is inconsistent, avd-swarm only drafts, a person merges.
- C7 already gives commit-pinned sources and citations, so the wiki index is an extension, not a new system.
