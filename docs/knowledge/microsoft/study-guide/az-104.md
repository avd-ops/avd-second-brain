# AZ-104 study guide

**Bottom line:** AZ-104 rewards exact limits and scopes: which SKU or tier unlocks a feature, which
role or policy effect does a job, and which way rules are evaluated. Learn the traps below and the
rest follows.

Back to the [study guide](README.md). The official skills outline is the
[AZ-104 study guide](https://learn.microsoft.com/credentials/certifications/resources/study-guides/az-104) (updated 2026-04-17); the domains and weights below follow it, and the
notes under them are ours. Where the [avd-landing-zone](https://github.com/avd-ops/avd-landing-zone)
uses a feature, the objective links the file.

## Objectives

### Manage Azure identities and governance (20 to 25%)

#### Entra users and groups

- **Know:** Create users, groups (security, Microsoft 365), assigned or dynamic membership. Group-based licensing and dynamic groups need Entra ID P1. A user needs a usage location before a license can be assigned. B2B guests and external collaboration settings. SSPR: methods, number required, registration.
- **Trap:** License assignment fails with no usage location set. Dynamic group rules cannot be combined with assigned members.

#### Access to Azure resources

- **Know:** Built-in roles: Owner, Contributor (no access management), Reader, User Access Administrator, Role Based Access Control Administrator. Scopes: management group, subscription, resource group, resource; inheritance flows down. Check access and deny assignments explain effective access.
- **Trap:** Entra directory roles and Azure RBAC roles are separate systems. Global Administrator has no Azure resource access until it elevates.

#### Subscriptions and governance

- **Know:** Policy effects: Deny, Audit, Append, Modify, DeployIfNotExists, AuditIfNotExists, DenyAction, Disabled. Initiatives group policies; exemptions carve out scope. Remediation tasks fix existing resources for Modify and DeployIfNotExists, using a managed identity. Locks: CanNotDelete and ReadOnly, inherited. Tags are not inherited unless a policy does it. Budgets alert and can trigger action groups but never stop spend by themselves. Management groups nest up to six levels below the root.
- **Trap:** A ReadOnly lock on a storage account blocks listing keys, because listKeys is a POST. Tools that use keys break.
- **See it built:** [governance.bicep](https://github.com/avd-ops/avd-landing-zone/blob/master/bicep/modules/governance.bicep)

### Implement and manage storage (15 to 20%)

#### Access to storage

- **Know:** Firewalls and virtual networks with the trusted Microsoft services exception. SAS types: account, service, user delegation (Entra credentials, blob only). Stored access policies (up to five per container) let you revoke SAS by editing or deleting the policy. Rotate keys with key1 and key2. Azure Files identity-based access with share-level RBAC plus NTFS.
- **Trap:** Regenerating a key invalidates every SAS signed with it. Revoking one ad hoc SAS without a stored access policy means rotating the key.

#### Storage accounts

- **Know:** Redundancy: LRS, ZRS, GRS, RA-GRS, GZRS, RA-GZRS. Object replication needs blob versioning on both accounts and change feed on the source. Encryption: Microsoft-managed keys by default; customer-managed keys in Key Vault with soft delete and purge protection; infrastructure encryption only at creation. AzCopy and Storage Explorer.
- **Trap:** Archive tier is not available on ZRS, GZRS or RA-GZRS accounts.

#### Azure Files and Blob

- **Know:** File shares, share snapshots and soft delete; containers and access levels; hot, cool, cold and archive tiers; rehydration from archive takes hours; lifecycle rules by days since modification, creation or last access; blob versioning and soft delete for blobs and containers.
- **Trap:** Last-access lifecycle rules need access tracking turned on first.

### Deploy and manage Azure compute resources (20 to 25%)

#### ARM templates and Bicep

- **Know:** Read parameters, variables, resources, outputs. Deploy with az deployment group create or New-AzResourceGroupDeployment. Incremental mode (default) leaves extra resources; Complete deletes what the template does not list. what-if previews. Export from a resource group; az bicep decompile turns ARM JSON into Bicep.
- **Trap:** Complete mode deletes resources in the resource group that the template omits. Read the mode in the question.
- **See it built:** [main.bicep](https://github.com/avd-ops/avd-landing-zone/blob/master/bicep/main.bicep)

#### Virtual machines

- **Know:** Sizes and resize (may need deallocate). Managed disks, data disks, disk types. Encryption at host needs the EncryptionAtHost feature registered on the subscription. Move VMs across resource groups and subscriptions (same region), or across regions with Resource Mover or Site Recovery. Availability sets (fault and update domains) vs zones. Scale sets: Flexible or Uniform orchestration, autoscale rules.
- **Trap:** You cannot add an existing VM to an availability set. You recreate it.

#### Containers

- **Know:** Container Registry SKUs Basic, Standard, Premium (geo-replication and private link in Premium). Container Instances: container groups, restart policies, sizing per container. Container Apps: environments, revisions, scale rules (HTTP, KEDA), scale to zero.
- **Trap:** ACI does not autoscale. When a question needs scaling on demand, the answer is Container Apps.

#### App Service

- **Know:** Plans set tier and scale; scale up (tier) vs scale out (instances, autoscale on Standard and above). Custom domains verified with a CNAME or A record plus the asuid TXT record. TLS bindings and managed certificates. Backups, VNet integration, access restrictions, private endpoints. Deployment slots on Standard and above, with swap.
- **Trap:** App settings marked as deployment slot settings stay with the slot during a swap; everything else moves.

### Implement and manage virtual networking (15 to 20%)

#### Virtual networks

- **Know:** Address spaces cannot overlap for peering. Azure reserves five addresses in every subnet. Peering is non-transitive; gateway transit and allow forwarded traffic enable hub designs. Standard public IPs (Basic SKU is retired). UDR next hops: virtual appliance, virtual network gateway, internet, none. Effective routes and Network Watcher next hop to troubleshoot.
- **Trap:** A /28 has 11 usable addresses, a /29 has 3. Peering A to B and B to C does not connect A to C.
- **See it built:** [network.bicep](https://github.com/avd-ops/avd-landing-zone/blob/master/bicep/modules/network.bicep)

#### Secure access

- **Know:** NSG rules by priority 100 to 4096, lowest number first, default rules at 65000 and up. Inbound: subnet NSG then NIC NSG; outbound the reverse. Application security groups group NICs in the same VNet. Bastion needs AzureBastionSubnet, /26 or larger; Developer, Basic, Standard and Premium SKUs. Service endpoints keep the public endpoint; private endpoints give a private IP and need private DNS.
- **Trap:** Traffic must be allowed by both the subnet NSG and the NIC NSG. One allow is not enough.
- **See it built:** [bastionDeveloper.bicep](https://github.com/avd-ops/avd-landing-zone/blob/master/bicep/modules/bastionDeveloper.bicep)

#### Name resolution and load balancing

- **Know:** Azure DNS public zones and record sets; private DNS zones linked to VNets, with auto-registration. Load balancer: Standard SKU, public or internal, backend pools, health probes, load-balancing rules, inbound NAT, outbound rules, session persistence.
- **Trap:** A VNet can link to many private zones but auto-register into only one.
- **See it built:** [privateDns.bicep](https://github.com/avd-ops/avd-landing-zone/blob/master/bicep/modules/privateDns.bicep)

### Monitor and maintain Azure resources (10 to 15%)

#### Monitoring

- **Know:** Metrics vs logs. Diagnostic settings route platform logs. KQL in Log Analytics. Alert rules (metric, log, activity log), action groups, alert processing rules to suppress or route. VM, storage and network insights. Network Watcher: IP flow verify, next hop, connection troubleshoot, Connection monitor, packet capture.
- **Trap:** To silence alerts during maintenance, use an alert processing rule. Disabling the alert rule is not the intended answer.
- **See it built:** [monitoring.bicep](https://github.com/avd-ops/avd-landing-zone/blob/master/bicep/modules/monitoring.bicep)

#### Backup and recovery

- **Know:** Recovery Services vault: Azure VMs, Azure Files, SQL in VM, MARS agent. Backup vault: managed disks, blobs, PostgreSQL, AKS. Policies set schedule and retention; soft delete protects deleted backups. Site Recovery replicates VMs to another region: test failover into an isolated VNet, failover, commit, re-protect, failback. Backup reports use a Log Analytics workspace.
- **Trap:** The vault must be in the same region as the VMs it backs up.
- **See it built:** [backup.bicep](https://github.com/avd-ops/avd-landing-zone/blob/master/bicep/modules/backup.bicep)

## Practice questions

Pick an answer before you open it. Then read why the others are wrong.

### Identities and governance

**Q1.** You try to assign a Microsoft 365 license to a new user and it fails. The tenant has free licenses. What do you check first?

- A. Whether the user has MFA
- B. The user's manager
- C. The user's usage location
- D. The user's job title

<details><summary>Answer</summary>

**C.** A license cannot be assigned without a usage location, because service availability varies by country.

</details>

**Q2.** You need a group whose members update automatically from the department attribute. Which license does the tenant need?

- A. Azure subscription Owner
- B. Entra ID P1
- C. Entra ID Free
- D. No license

<details><summary>Answer</summary>

**B.** Dynamic membership groups need Entra ID P1 (or higher) for the members.

</details>

**Q3.** An auditor must manage who has access to a subscription but must not create or change resources. Which role fits?

- A. Contributor
- B. User Access Administrator
- C. Owner
- D. Reader

<details><summary>Answer</summary>

**B.** User Access Administrator manages role assignments only. Owner can also change resources; Contributor cannot manage access.

</details>

**Q4.** After a ReadOnly lock is applied to a storage account, a tool that connects with account keys stops working. Why?

- A. The lock turned on the firewall
- B. The lock rotated the keys
- C. ReadOnly blocks all data-plane reads
- D. Listing keys is a POST operation, which the lock blocks

<details><summary>Answer</summary>

**D.** ReadOnly blocks write operations on the management plane, and listKeys is a POST. Data access through Entra ID still works.

</details>

**Q5.** Every resource, including existing ones, must carry the CostCenter tag of its resource group. What do you use?

- A. The built-in Modify policy to inherit a tag from the resource group, with a remediation task
- B. A Deny policy for missing tags
- C. Tag the resource group only; tags inherit
- D. A CanNotDelete lock

<details><summary>Answer</summary>

**A.** Tags do not inherit. The Modify policy adds them to new resources, and a remediation task (using a managed identity) fixes existing ones.

</details>

**Q6.** How many levels of management groups can you nest below the root management group, not counting subscriptions?

- A. Six
- B. Three
- C. Unlimited
- D. Ten

<details><summary>Answer</summary>

**A.** The hierarchy supports six levels of depth, excluding the root and the subscription level.

</details>


### Storage

**Q7.** You cannot move blobs to the archive tier in a storage account. Which configuration explains it?

- A. The account has versioning on
- B. The container is private
- C. The account uses LRS
- D. The account uses GZRS

<details><summary>Answer</summary>

**D.** Archive is not supported on ZRS, GZRS or RA-GZRS accounts.

</details>

**Q8.** You issued several SAS tokens tied to a stored access policy. One must be revoked now without rotating account keys. What do you do?

- A. Regenerate key1
- B. Delete or change the stored access policy
- C. Shorten the SAS in the client
- D. Turn on the storage firewall

<details><summary>Answer</summary>

**B.** SAS tokens linked to a stored access policy follow it, so editing or deleting the policy revokes them.

</details>

**Q9.** You set up object replication from account A to account B. What must be turned on?

- A. Soft delete on both
- B. Hierarchical namespace on both
- C. Change feed on B only
- D. Blob versioning on both, and change feed on A

<details><summary>Answer</summary>

**D.** Object replication requires versioning on source and destination and change feed on the source.

</details>

**Q10.** Developers need a SAS that does not depend on the storage account keys. Which kind do you issue?

- A. Shared Key
- B. Service SAS
- C. User delegation SAS
- D. Account SAS

<details><summary>Answer</summary>

**C.** A user delegation SAS is signed with Entra credentials and works for Blob storage.

</details>

**Q11.** You will encrypt a storage account with a customer-managed key in Key Vault. What must the vault have?

- A. A private endpoint
- B. RBAC turned off
- C. Soft delete and purge protection
- D. The Premium SKU

<details><summary>Answer</summary>

**C.** Customer-managed keys need a vault with soft delete and purge protection, so the key cannot be lost by accident.

</details>

**Q12.** VMs reach a storage account through a new private endpoint, but the name still resolves to a public IP. What is missing?

- A. A private DNS zone privatelink.blob.core.windows.net linked to the VNet
- B. A service endpoint on the subnet
- C. A public DNS zone
- D. A UDR to the storage account

<details><summary>Answer</summary>

**A.** Private endpoints need DNS to return the private IP, usually through the privatelink zone linked to the VNet.

</details>


### Compute

**Q13.** An existing VM must join an availability set. What do you do?

- A. Resize the VM
- B. Move the VM to the set's resource group
- C. Recreate the VM in the availability set from its disks
- D. Change the VM's availability setting in the portal

<details><summary>Answer</summary>

**C.** Availability set membership is set at creation. You recreate the VM, for example from its existing disks.

</details>

**Q14.** You redeploy a template to a resource group and want any resource not in the template removed. Which deployment mode?

- A. What-if
- B. Validate
- C. Incremental
- D. Complete

<details><summary>Answer</summary>

**D.** Complete mode deletes resources in the resource group that the template does not declare. Incremental is the default.

</details>

**Q15.** You have an exported ARM JSON template and want a Bicep file. Which command?

- A. az bicep build
- B. az bicep decompile
- C. az deployment group export
- D. az bicep publish

<details><summary>Answer</summary>

**B.** decompile converts JSON to Bicep; build goes the other way.

</details>

**Q16.** A web app needs a staging slot. Which is the lowest App Service plan tier that supports deployment slots?

- A. Standard
- B. Basic
- C. Free
- D. Premium

<details><summary>Answer</summary>

**A.** Deployment slots start at Standard.

</details>

**Q17.** After a slot swap, production started using the staging database string. How do you keep each slot's string in place?

- A. Lock the app
- B. Turn off auto swap
- C. Mark the connection string as a deployment slot setting
- D. Use a different plan for staging

<details><summary>Answer</summary>

**C.** Settings marked as slot settings stick to their slot during a swap.

</details>

**Q18.** A workload in containers must scale out on HTTP traffic and scale to zero when idle. What do you use?

- A. Azure Container Registry tasks
- B. Azure Container Instances
- C. Azure Container Apps
- D. A single VM running Docker

<details><summary>Answer</summary>

**C.** Container Apps scales on HTTP and KEDA rules, down to zero. Container Instances has no autoscale.

</details>

**Q19.** Deploying a VM with encryption at host fails with a feature error. What is the first step?

- A. Turn on Azure Disk Encryption
- B. Register the EncryptionAtHost feature on the subscription
- C. Add a Key Vault
- D. Use an unmanaged disk

<details><summary>Answer</summary>

**B.** Encryption at host needs the Microsoft.Compute EncryptionAtHost feature registered on the subscription.

</details>


### Networking

**Q20.** VNet A peers with B, and B peers with C. VMs in A cannot reach C. Why?

- A. Global peering is required
- B. NSGs block ICMP
- C. Address spaces overlap
- D. Peering is non-transitive

<details><summary>Answer</summary>

**D.** Peering is not transitive. Peer A and C directly, or route through a hub appliance with UDRs and forwarded traffic allowed.

</details>

**Q21.** How many addresses can you assign to VMs in a /28 subnet?

- A. 16
- B. 14
- C. 11
- D. 8

<details><summary>Answer</summary>

**C.** 16 addresses minus the five Azure reserves leaves 11.

</details>

**Q22.** An NSG has rule 100 Deny TCP 3389 from Any and rule 200 Allow TCP 3389 from the admin subnet. What happens to RDP from the admin subnet?

- A. Denied only on the NIC
- B. Allowed, because more specific rules win
- C. Allowed, because allow wins
- D. Denied, because rule 100 is evaluated first

<details><summary>Answer</summary>

**D.** Rules are processed by priority, lowest number first, and processing stops at the first match.

</details>

**Q23.** You add Azure Bastion to a VNet. What subnet do you need?

- A. Any subnet, /29
- B. GatewaySubnet, /27
- C. A delegated subnet for Microsoft.Network/bastionHosts
- D. A subnet named AzureBastionSubnet, /26 or larger

<details><summary>Answer</summary>

**D.** Bastion needs a subnet named exactly AzureBastionSubnet, /26 or larger.

</details>

**Q24.** You want VMs in a VNet to register their names automatically in two private DNS zones. What happens?

- A. You need a DNS forwarder
- B. Both links can auto-register
- C. Auto-registration needs a public zone
- D. Only one zone link per VNet can have auto-registration

<details><summary>Answer</summary>

**D.** A VNet can auto-register in only one private DNS zone; other links are resolution only.

</details>

**Q25.** You need to know whether an NSG allows a given packet to reach a VM, and which rule decides. Which tool?

- A. Connection monitor
- B. IP flow verify
- C. Packet capture
- D. Traffic analytics

<details><summary>Answer</summary>

**B.** IP flow verify tests a 5-tuple against the effective rules and names the deciding rule.

</details>


### Monitor and maintain

**Q26.** Alerts must be silenced during a Saturday maintenance window without changing the alert rules. What do you create?

- A. A budget
- B. A resource lock
- C. An action group with no actions
- D. An alert processing rule with a schedule

<details><summary>Answer</summary>

**D.** Alert processing rules suppress or reroute notifications on a schedule.

</details>

**Q27.** You back up VMs in East US to a Recovery Services vault. Where must the vault be?

- A. West US, for geo-safety
- B. Any region
- C. The paired region only
- D. East US

<details><summary>Answer</summary>

**D.** For Azure VM backup, the vault must be in the same region as the VMs. Use GRS on the vault for cross-region safety.

</details>

**Q28.** You need snapshot-based backup of Azure managed disks with a retention policy. Which vault?

- A. Site Recovery vault
- B. Backup vault
- C. Key Vault
- D. Recovery Services vault

<details><summary>Answer</summary>

**B.** Azure Disk Backup uses a Backup vault. Recovery Services vaults handle VMs, Azure Files and SQL in VMs.

</details>

**Q29.** You test Site Recovery failover without affecting production. What do you do?

- A. Fail over and fail back right away
- B. Run a planned failover
- C. Run a test failover into an isolated VNet
- D. Stop replication, then fail over

<details><summary>Answer</summary>

**C.** Test failover creates VMs in an isolated network while replication continues. Clean it up afterward.

</details>

**Q30.** You need latency and reachability between a VM and an on-premises endpoint measured over time, with alerts. Which tool?

- A. Next hop
- B. IP flow verify
- C. Connection monitor
- D. Effective routes

<details><summary>Answer</summary>

**C.** Connection monitor runs continuous tests and feeds Azure Monitor metrics and alerts.

</details>
