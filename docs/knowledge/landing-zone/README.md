# Landing zone

How an AVD landing zone gets built and kept healthy with Azure-native tooling: Bicep and Azure Verified Modules, networking and private endpoints, vCPU quota, resource providers, and running every step from Azure Cloud Shell. Each rule below came out of a real run of [avd-landing-zone](https://github.com/avd-ops/avd-landing-zone) and links the lesson that holds the detail ([decision 0008](../decisions/0008-learned-knowledge-stays-where-it-happened.md)). The exact errors are in [known errors](../troubleshooting/README.md).

The landing zone's scope is Entra ID only, greenfield and private by default ([avd-landing-zone decision 0001](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/decisions/0001-cloud-native-scope.md)).

## Orchestrating the five control planes

[avd-landing-zone](https://github.com/avd-ops/avd-landing-zone) is the top-level orchestrator and deployment portal (`deploy.avd-ops.dev/portal/`) over five single-purpose control-plane packs ([avd-ops decision 0009](https://github.com/avd-ops/avd-ops/blob/main/docs/knowledge/decisions/0009-split-landing-zone-into-five-control-planes.md)):

- **[avd-entra](https://github.com/avd-ops/avd-entra)** (Microsoft Graph API + PowerShell): security groups stamped with `[avd-ops-<prefix>-<env>]` (`[avd-ops-<prefix>-<env>] AVD Users`, `[avd-ops-<prefix>-<env>] AVD Users (<pool>)`, `[avd-ops-<prefix>-<env>] AVD Admins`, `[avd-ops-<prefix>-<env>] AVD Break-Glass Exclude`, and dynamic `[avd-ops-<prefix>-<env>] AVD Session Hosts`), Conditional Access policies (aligned AVD and Windows Cloud Login MFA with the feed excluded, `reportOnly` by default), Entra Kerberos cloud trust preparation, and optional greenfield lab user and license assignment. Emits `avd-ops-entra-manifest/v1` (`contracts/entra-manifest.schema.json`) and `entra-run-manifest.json` (`created: true|false` per object ID) for `Remove-AvdEntra.ps1 -DiscardLastCopy`.
- **[avd-intune](https://github.com/avd-ops/avd-intune)** (Microsoft Graph `deviceManagement` API + PowerShell): automatic MDM enrollment, Windows 11 multi-session Settings Catalog profiles (`FSLogix`, `Watermarking`, `ScreenCaptureProtection`, `SessionTimeLimits`, `DefenderVdiExclusions`), and compliance policies stamped with `[avd-ops-<prefix>-<env>]` and scoped to the session-host device groups from `avd-entra`. Emits `avd-ops-intune-manifest/v1` (`contracts/intune-manifest.schema.json`) and `intune-run-manifest.json` for `Remove-AvdIntune.ps1 -DiscardLastCopy`.
- **[avd-m365](https://github.com/avd-ops/avd-m365)** (Microsoft Graph API + PowerShell): greenfield M365 workplace readiness, OneDrive Known Folder Move (`KFMSilentOptIn` with runtime tenant ID lookup) and Silent Account Configuration, new Teams VDI optimization (`SlimCore`), and Microsoft 365 Apps Shared Computer Activation stamped with `[avd-ops-<prefix>-<env>]`. Emits `avd-ops-m365-manifest/v1` (`contracts/m365-manifest.schema.json`) and `m365-run-manifest.json` for `Remove-AvdM365.ps1 -DiscardLastCopy`.
- **[avd-azure](https://github.com/avd-ops/avd-azure)** (Azure ARM + Bicep + PowerShell): the Azure resource-plane infrastructure extracted from `avd-landing-zone` (subscription and workload Bicep templates, Azure Verified Modules, multi-pool host pools, FSLogix Azure Files and Private Link networking, session host image and rollout scripts, Bastion Developer jumpbox, and PSRule checks). Consumes `avd-ops-entra-manifest/v1` and emits `avd-ops-azure-outputs/v1` (`contracts/azure-outputs.schema.json`).
- **[avd-power-platform](https://github.com/avd-ops/avd-power-platform)** (`Microsoft.PowerPlatform` Bicep + Power Platform CLI + unpacked Power Automate solutions): optional Day-2 low-code environment (`[avd-ops-<prefix>-<env>] AVD Day-2 Automation`), business vs. non-business DLP policy baseline (`[avd-ops-<prefix>-<env>] AVD Day-2 Automation Strict DLP Policy`), VNet subnet delegation (`Microsoft.PowerPlatform/enterprisePolicies`), and source-controlled approval workflows for self-service AVD access requests and host start/drain/deallocate requests in Teams. Consumes `avd-ops-entra-manifest/v1` and `avd-ops-azure-outputs/v1`, and emits `avd-ops-power-platform-manifest/v1` (`contracts/power-platform-manifest.schema.json`) and `power-platform-run-manifest.json` for `Remove-AvdPowerPlatform.ps1 -DiscardLastCopy`.
- **Keep `avd-power-platform` and `avd-swarm` in separate lanes.** `avd-power-platform` holds deterministic, user-facing approval workflows inside the tenant's Teams and Power Automate environment; [avd-swarm](https://github.com/avd-ops/avd-swarm) holds agentic reasoning, investigation, and GitHub-gated change plans. Neither duplicates the other.
- **Tenant control-plane stamp and run-manifest teardown.** Graph, Intune, M365, and Power Platform objects share a flat tenant namespace with no resource-group container. Idempotent `Deploy-Avd*.ps1` scripts stamp display names with `[avd-ops-<prefix>-<env>]` and record `created: true|false` per object ID in a local `*-run-manifest.json` so `Remove-Avd*.ps1` deletes only objects created by the run (never pre-existing brownfield objects matched on `GET`) and gates stateful deletions behind `-DiscardLastCopy` ([avd-entra PR #2](https://github.com/avd-ops/avd-entra/pull/2), [avd-intune PR #2](https://github.com/avd-ops/avd-intune/pull/2), [avd-m365 PR #2](https://github.com/avd-ops/avd-m365/pull/2), [avd-power-platform PR #2](https://github.com/avd-ops/avd-power-platform/pull/2)).
- **Query the tenant GUID at deploy time for OneDrive Known Folder Move (`KFMSilentOptIn`).** OneDrive KFM policy definitions require the tenant GUID, which must never be committed in static JSON templates. Query `GET https://graph.microsoft.com/v1.0/organization?$select=id` at deploy time and inject it only in memory ([avd-m365 PR #2](https://github.com/avd-ops/avd-m365/pull/2)).
- **Pass `az rest` request bodies via UTF-8 (no BOM) `@file`.** Passing nested Graph Settings Catalog or Conditional Access JSON inline to `az rest --body` breaks across PowerShell, Bash, and Windows argument escaping. Write UTF-8 without BOM to a temporary file and pass `--body "@$tempFile"` ([avd-entra PR #2](https://github.com/avd-ops/avd-entra/pull/2), [avd-intune PR #2](https://github.com/avd-ops/avd-intune/pull/2)).
- **Use forward-slash (`/`) zip entry paths when packing Power Platform solutions on Windows.** `Compress-Archive` on Windows writes backslash (`\`) entry paths in `.zip` archives, which breaks Dataverse and `pac solution import` lookup of `[Content_Types].xml` and `Other/Solution.xml`. Build solution `.zip` files with `[System.IO.Compression.ZipFile]` / `ZipArchive` using forward-slash (`/`) entry names ([avd-power-platform PR #2](https://github.com/avd-ops/avd-power-platform/pull/2)).
- **Verify Entra Kerberos storage account app owners before consenting or excluding from MFA.** Anyone with application-registration permission can create a look-alike app named `[Storage Account] <storageFqdn>`, whereas Azure's `Microsoft.Storage` resource provider creates the real app either with zero owners (when deployed by a service principal) or with the signed-in deploying user as owner (when deployed interactively via ARM). Query `GET /v1.0/applications/{id}/owners?$select=id` on every candidate and accept only an app with zero owners or whose owners are all directory administrators (`GET /v1.0/directoryRoles` + `/members`) or the signed-in operator (`GET /v1.0/me`); refuse to grant `AllPrincipals` admin consent or Conditional Access MFA exclusions when any non-admin owner is present ([avd-entra PR #2](https://github.com/avd-ops/avd-entra/pull/2), [lesson 0038](https://github.com/avd-ops/avd-landing-zone/blob/master/build/lessons/0038-storage-kerberos-app-operator-owner.md), [avd-landing-zone PR #124](https://github.com/avd-ops/avd-landing-zone/pull/124)).
- **Synthesize contract-valid handoff manifests in orchestrator `-DryRun` mode when sibling repos are absent, using only the zero GUID (`00000000-0000-0000-0000-000000000000`) for placeholder IDs.** In a multi-repo orchestrator (`Invoke-AvdControlPlanes.ps1 -DryRun`), CI runners check out only `avd-landing-zone` without sibling `../avd-entra`, `../avd-intune`, `../avd-m365`, `../avd-azure`, or `../avd-power-platform` directories. When `-DryRun` is set and a sibling checkout path is absent, emit deterministic contract-compliant handoff manifests directly so offline Pester tests remain hermetic, and use only `00000000-0000-0000-0000-000000000000` for placeholder GUID fields because `report.test.mjs` requires every literal GUID in `bicep/`, `parameters/`, and `scripts/` to be listed in `PUBLIC_IDS` (`site/portal/report.js`) ([avd-landing-zone PR #123](https://github.com/avd-ops/avd-landing-zone/pull/123)).

## Quota and regions

- New subscriptions start with 0 vCPU quota for most VM families, separate from the regional limit. Check family and regional quota per region before deploying, and request small increases through `Microsoft.Quota` ([lesson 0013](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0013-vcpu-quota.md)).
- A quota check after deployment must not count the landing zone's own hosts twice: they are already in `used` ([lesson 0024](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0024-quota-counts-deployed-hosts.md)).
- Test in a region without availability zones (North Central US) as well as a zonal one. ARM leaves empty properties out, so a zone list can be missing rather than empty ([lesson 0001](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0001-nat-gateway-pip-zones.md), [lesson 0021](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0021-arm-omits-empty-properties.md)).
- Latency measured from Cloud Shell says nothing about users: measure from where they are, against endpoints verified to be regional ([lesson 0003](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0003-region-latency.md)).

## Resource providers

- `Get-AzResourceProvider -ProviderNamespace` returns one object per region. Read the provider through ARM REST when the cmdlet reshapes data ([lesson 0005](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0005-provider-per-region.md)).
- Register through the ARM `register` API, which returns at once, and show progress while waiting. EncryptionAtHost takes effect only after Microsoft.Compute is registered again ([lesson 0006](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0006-provider-registration.md)).

## Bicep and Azure Verified Modules

- An AVM module's nested defaults (zones, SKUs, locations) apply when the parent doesn't set them. Compile the template and walk the nested deployments before adopting a module ([lesson 0001](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0001-nat-gateway-pip-zones.md)).
- Don't assume where a module puts child resources. Private endpoints land in their target's resource group, so look them up by target ID ([lesson 0010](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0010-private-endpoint-rg.md)).
- `readEnvironmentVariable` returns an empty string, not its default, when the variable is set but empty. Guard optional variables with `empty(...)` ([lesson 0004](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0004-empty-env-var.md)).
- Keep `bicepconfig.json` strict and fix the cause rather than suppressing a rule ([lesson 0019](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0019-bicep-authoring.md)). For PSRule, suppress only with a reason and a narrow selector, and point it at an explicit Bicep binary ([lesson 0018](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0018-psrule.md)).
- Pin every CI tool (Bicep, PSRule and its Azure rules, PSScriptAnalyzer, Pester) and use the same versions wherever the same check runs, including PSRule's live Well-Architected review. A floating `latest` lets a release change a result with no commit, and the `microsoft/ps-rule` action always installs the newest rules module, so install pinned modules yourself ([ci.md](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/ci.md)).
- `bicep snapshot` gives an offline what-if: run it on a parameter file at the base commit, then `--mode validate` at the PR, and it prints the resource and property changes in what-if's format with placeholder IDs and no sign-in. `reference()` and `list*()` stay unevaluated, so a live what-if still has the last word. Checkov 3.3 added nothing for Bicep (parser errors on modern Bicep; on compiled ARM it sees only the top-level deployments), and ARM-TTK's useful tests already became the Bicep linter's defaults ([ci.md](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/ci.md)).
- Ignore build output where it's written, never `*.json` across the repo: a file Bicep loads at compile time must be committed ([lesson 0027](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0027-gitignore-json-data-files.md)).
- Keep the compiled subscription ARM template (`bicep build-params <file>.bicepparam --stdout`) under ARM's 4 MB (`4,194,304`-byte) HTTP request limit (`RequestContentTooLarge`). Because `bicep build-params --stdout` emits 2-space pretty-printed JSON with all nested AVM `@description` metadata inlined, each reference to `br/public:avm/res/compute/virtual-machine:0.22.3` adds ~676 KB at `main.bicep`'s indentation depth (including `vm_nic` and 11 extension sub-deployments), even behind a `for`-loop whose array defaults to empty (`count: 0`). Share one `avm/res/compute/virtual-machine` loop in `sessionHosts.bicep` across the primary pool and `additionalPools`, register additional pools' hosts in a lightweight companion module (`registerPoolHosts.bicep`), and guard `[Text.Encoding]::UTF8.GetByteCount($raw.templateJson) -lt 4194304` in `Template.Tests.ps1` ([lesson 0037](https://github.com/avd-ops/avd-landing-zone/blob/master/build/lessons/0037-subscription-template-4mb-limit.md), [avd-landing-zone PR #124](https://github.com/avd-ops/avd-landing-zone/pull/124)).

## Scripts that run it

- Give operators self-contained command blocks for Cloud Shell, with no placeholders to fill in. Long operations must survive a disconnect and say how to check on them ([lesson 0015](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0015-cloud-shell-ergonomics.md)).
- Anything that can take more than a few seconds prints a line before it starts, and "fixed" means done, not started ([lesson 0006](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0006-provider-registration.md)).
- Every loop over remote calls ends on error, including non-terminating errors and empty results ([lesson 0008](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0008-non-terminating-loops.md)).
- Check each Az and Graph cmdlet call against its documented parameter sets, and keep mocks no more permissive than the real cmdlet ([lesson 0014](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0014-cmdlet-parameter-sets.md)). Emit items from functions instead of returning one array ([lesson 0009](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0009-array-unrolling.md)).
- Lint with the PSScriptAnalyzer version CI installs; use approved verbs and singular nouns ([lesson 0016](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0016-analyzer-version.md)). Reserve state-changing verbs (`New-*`, `Set-*`, `Remove-*`) for functions that declare `[CmdletBinding(SupportsShouldProcess)]`, and name internal pure helpers that build payloads or format values with `Build-*`, `ConvertTo-*`, `Resolve-*`, or `Format-*` and singular nouns so `PSUseShouldProcessForStateChangingFunctions` and `PSUseSingularNouns` stay clean ([avd-entra PR #2](https://github.com/avd-ops/avd-entra/pull/2)). Offline tests provide every external tool they touch ([lesson 0020](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0020-hermetic-harness.md)).
- When a PowerShell script shells out to Python on Windows, skip the Microsoft Store execution alias (`*WindowsApps*`) and resolve a real interpreter (`python3`, `python`, `py`, or `$env:LOCALAPPDATA\Programs\Python\Python*\python.exe`) so a missing Store alias does not silently print `"Python was not found..."` and skip validation ([avd-intune PR #2](https://github.com/avd-ops/avd-intune/pull/2), [avd-m365 PR #2](https://github.com/avd-ops/avd-m365/pull/2)).
- Never make a person remember a secret the platform can generate and reset, such as the break-glass password ([lesson 0002](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0002-break-glass-password.md)).
- When running `deploy.sh` or sandbox batches outside Cloud Shell under a Conditional Access MFA policy on Azure Resource Management, `Az` PowerShell (`Connect-AzAccount`) and `az` CLI maintain separate token caches: sign in to `az` explicitly with `az login --scope https://management.core.windows.net//.default` (or `--claims-challenge`) so `deploy.sh` does not fail with `AADSTS50076`. On Windows, any Bash `az` wrapper on `PATH` must have a companion `az.cmd` shim beside it so PowerShell does not resolve the extensionless file as a document (`Cannot run a document in the middle of a pipeline`), and `git config core.autocrlf` must be `false` so LF-normalized contract files (`contracts/fact-register.json`) keep their pinned SHA-256 digests.

## Working from a VM inside the landing zone

Cloud Shell sits outside the landing zone's network, so it can't reach private endpoints such as the private Key Vault or an SMB-only profile share, and its sessions time out. avd-landing-zone offers an opt-in jumpbox reached through Azure Bastion Developer ([avd-landing-zone decision 0019](https://github.com/avd-ops/avd-landing-zone/blob/master/build/decisions/0019-jumpbox-bastion-developer.md)). What Microsoft Learn says about the Developer SKU, read on 2026-10-21 ([SKU comparison](https://learn.microsoft.com/azure/bastion/bastion-sku-comparison), [configuration settings](https://learn.microsoft.com/azure/bastion/configuration-settings), [Entra ID authentication](https://learn.microsoft.com/azure/bastion/bastion-entra-id-authentication)):

- **Bastion is not always billed by the hour.** Developer has no hourly or outbound data charge, needs no AzureBastionSubnet or public IP, and deploys in seconds from a shared pool. "No Bastion because it costs money" holds only for Basic and higher.
- **One connection at a time, same VNet only.** Developer doesn't follow peering, so it reaches only VMs in the VNet it references: put the jumpbox in the spoke, not in a hub.
- **Portal only, and no Microsoft Entra sign-in.** No native client, custom ports, shareable links or file transfer; Entra sign-in needs Basic in the portal and Standard for the native client. With Developer the OS account is local: set a one-time password through the management plane (the VM access extension's protected settings) on each connect instead of storing one.
- **Only in some regions.** The list includes North Central US, Central US and East US 2, but not East US, South Central US or West US 2 and 3; check it before choosing a recovery region. Microsoft calls Developer unsuitable for production.
- *Unverified:* not yet seen in a real run. A sandbox run is to confirm the deployment, the role a connection needs and the one-time password flow.

## Publishing the deployment portal

- **Move a portal onto the shared engine with a golden test first.** The deployment and assessment portals share the avd-ops portal engine ([spec](https://github.com/avd-ops/avd-ops/blob/main/docs/portal-engine-spec.md)): UMD classic scripts each consumer copies at a release tag, pinned by sha256 in `site/assets/engine.lock.json` and marked `-text` in `.gitattributes` so line endings never change the hash. Before delegating to the engine, record every block the portal builds (each Run in choice, state lines, quoting) as a golden fixture, and keep it byte-equal through the move. If the base branch changes an input fixture meanwhile, regenerate the golden only after showing the base branch's pre-move code produces the same output. A classic script in an ESM repo needs a nested `package.json` with `"type": "commonjs"` (avd-ops known error `classic-script-in-esm-repo`). Done this way in [avd-current-state #50](https://github.com/avd-ops/avd-current-state/pull/50).

- Set the repo's **Settings > Pages > Source** to **GitHub Actions** before relying on a Pages workflow. While the source is a branch folder (`docs/`), GitHub's own branch build runs after the next push and replaces what the workflow deployed, so the portal vanishes. Switching the source doesn't republish anything: run the Pages workflow once after the switch ([GitHub Pages publishing sources](https://docs.github.com/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)).
- The portal is static and runs from any host that serves `site/portal` with `site/assets` beside it. To host a copy in a subscription instead of GitHub Pages, avd-landing-zone's `Publish-AvdPortal.ps1` offers Azure Static Web Apps or a storage static website ([avd-landing-zone decision 0017](https://github.com/avd-ops/avd-landing-zone/blob/master/build/decisions/0017-portal-hosting.md)). What decides between them:
  - Static Web Apps **Free** has only the preconfigured sign-in providers, and its Entra provider accepts any Microsoft account; GitHub sign-in is on too. "Signed in" is not access control: lock routes to a custom role given by invitation (25 invitations on Free). Single-tenant sign-in, IP restrictions and private endpoints need **Standard**, about $9 a month ([hosting plans](https://learn.microsoft.com/azure/static-web-apps/plans), [quotas](https://learn.microsoft.com/azure/static-web-apps/quotas), [authentication](https://learn.microsoft.com/azure/static-web-apps/authentication-authorization)).
  - Free has no SLA and 100 GB of bandwidth a month with no overage: past it, the site stops serving rather than costing money ([quotas](https://learn.microsoft.com/azure/static-web-apps/quotas)).
  - Static Web Apps resources are created only in centralus, eastus2, westus2, westeurope and eastasia. The landing zone's allowed-locations guardrail permits only its own region, so in any other region it denies the resource; check the policy before creating anything. *Unverified:* inferred from the policy and the region list, not yet seen in a real run.
  - Without a linked GitHub or Azure DevOps repo, the only way to upload is the Static Web Apps CLI (npm) with the site's deployment token, a long-lived secret. Pass it in `SWA_CLI_DEPLOYMENT_TOKEN`, never on a command line or in output, and reset it after the upload (`resetapikey`) ([CLI deploy](https://learn.microsoft.com/azure/static-web-apps/static-web-apps-cli-deploy), [token management](https://learn.microsoft.com/azure/static-web-apps/deployment-token-management)).
  - A storage static website needs neither npm nor a token: the operator's own sign-in uploads with Storage Blob Data Contributor, and turning the website on needs `blobServices/write` (Contributor has it). It has no sign-in at all (anonymous read of `$web`), though the storage firewall's IP and VNet rules do apply. Each blob is served with the Content-Type it was uploaded with, so set it on upload ([static website](https://learn.microsoft.com/azure/storage/blobs/storage-blob-static-website), [FAQ](https://learn.microsoft.com/azure/storage/blobs/static-website-hosting-faq)).
- Every GitHub Pages project site of one account shares the origin `<owner>.github.io`, and with it local storage, and Pages sends no CSP or framing headers. Give the portal its own origin with a custom domain, or host it where `staticwebapp.config.json` can send the headers. *Unverified:* from a design red team, not a real incident.
- A project site's custom domain (the portal's is `deploy.avd-ops.dev`) is set in **Settings > Pages**. A site deployed by an Actions workflow needs no `CNAME` file: GitHub ignores it there. Once the domain is set, GitHub redirects `<owner>.github.io/<repo>/<path>` to the same path on the domain, so old links keep working, but a page at the site root becomes the domain's home page: point it at what the domain is for ([managing a custom domain](https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site), [about custom domains](https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site/about-custom-domains-and-github-pages)). The DNS steps and the proxied-record trap are on the [operations page](../operations/README.md).
- Under a sticky header, `scrollIntoView({ block: 'start' })` and anchor links land the target under the header. Set `scroll-padding-top` on `html` to the header's height plus a gap, and compare a position with the header's height rather than 0 when deciding whether something has scrolled out of view.
- A page on a host that sends no security headers can still carry a `Content-Security-Policy` in a `<meta http-equiv>` tag, but only part of one: `frame-ancestors`, `report-uri` and `sandbox` are ignored there, so clickjacking protection needs a real response header ([MDN: CSP meta element](https://developer.mozilla.org/docs/Web/HTTP/Headers/Content-Security-Policy#csp_in_meta_elements)). A policy with `script-src 'self'` means no inline `<script>` and no `on*=` attributes: move the page's code to a file first. The landing zone's portal does this (`portal-page.js`, [portal README](https://github.com/avd-ops/avd-landing-zone/blob/master/site/portal/README.md)).
- A page that hands out commands must treat every value that reaches a command as input, whatever its source: the settings panel, settings saved in the browser earlier, and the context a script wrote into its own state line. One pattern per setting, taken from the Bicep parameters, and anything else dropped and named. The scripts also write their commit into the state line and the host writes the page's build commit into its config, so an old page can say "the scripts are newer than me" instead of producing a wrong command.
- In real-browser Playwright tests (`build/tests/portal/browser/portal.browser.test.mjs`), navigate to the wizard step slide that owns a collapsible `<details class="panel">` (such as `#control-planes-panel` inside `#size-panel`) and click `<details> > summary` before interacting with buttons inside the panel; JSDOM (`portal-browser.test.mjs`) dispatches `.click()` on hidden or collapsed elements without checking visibility or layout, whereas Chromium enforces actionability and sets `#steps button[aria-current="step"]` `aria-label` to the full `${i + 1}. ${STEPS[i].title}` string (with `, done` appended once the step is done) ([avd-landing-zone PR #123](https://github.com/avd-ops/avd-landing-zone/pull/123)).
- Pin GitHub Actions to a commit SHA with the version tag beside it (`uses: actions/checkout@<sha> # v4.4.0`): a tag moves, a SHA does not, and the comment keeps Dependabot and readers informed ([GitHub: using third-party actions](https://docs.github.com/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions#using-third-party-actions)). Resolve a tag to its SHA with `git ls-remote --tags <repo> refs/tags/<tag>`.
- A portal's "Report a problem" redaction has to find emails before the operator's own terms. If it runs terms first, a company name typed as a term breaks `user@contoso.com` into `user@<custom-1>.com`, and the user name stays in a public issue. The shared engine's `redact.js` (avd-ops portal engine 1.1.0) does emails, tenant and domain names first; the landing zone's `site/portal/report.js` still runs terms first ([avd-ops #59](https://github.com/avd-ops/avd-ops/pull/59), engine spec section 6.6).
- A prefilled new-issue link has a length limit, so the body gets cut. Cut whole lines from the middle and keep the head and tail. Shorten any single line over about 400 characters first, though: one minified JSON or ARM error line otherwise leaves an empty body that still reports nothing cut ([avd-ops #59](https://github.com/avd-ops/avd-ops/pull/59)).
- Redact a report's title and body as one text, so one value gets one placeholder number in both. When the title is cut to length, don't leave half a placeholder. Redact the body again after the operator edits it, since an edit can bring the value back ([avd-current-state #51](https://github.com/avd-ops/avd-current-state/pull/51)).
- A publish step that checks allowed-locations policy has to treat assignments that share no region as blocked, not as "no policy". Intersecting two assignments' lists can give an empty set, which is different from having no assignment at all. avd-current-state's `Get-AvdcsPortalHostRegion` returns `$null` only when there is no policy; the landing zone's `Get-AvdPortalHostRegion` doesn't make that distinction yet ([avd-current-state #51](https://github.com/avd-ops/avd-current-state/pull/51)).
- Republishing to Static Web Apps: GET the site before the PUT, and keep its plan. A PUT with `Free` downgrades a site someone moved to Standard. Reset the deployment token in a `finally` so a failed upload doesn't leave a live token ([avd-current-state #51](https://github.com/avd-ops/avd-current-state/pull/51)).
- A published copy that pins a repo and ref should clone into its own folder (`~/avd-current-state-pinned`), so the default clone keeps following the default branch. Stop the block when `git checkout` of the ref fails instead of running whatever is checked out. Check the ref on the remote (`git ls-remote`) before publishing ([avd-current-state #51](https://github.com/avd-ops/avd-current-state/pull/51)).
- A vendored file pinned by commit (an `engine.lock.json` naming a branch commit) needs its PR merged with a merge commit, not squashed, or the pinned commit never lands on `main` ([avd-ops #59](https://github.com/avd-ops/avd-ops/pull/59)).

## Well-Architected review

The landing zone's own review is an opt-in preflight section that only warns ([avd-landing-zone decision 0009](https://github.com/avd-ops/avd-landing-zone/blob/master/build/decisions/0009-well-architected-review.md)); avd-swarm's proposed chat review in avd-buddy reads its `waf-*` results instead of repeating them and asks the operator only what reads can't show ([avd-swarm waf-review spec](https://github.com/avd-ops/avd-swarm/blob/main/docs/waf-review.md)). Checked on 2026-10-20:

- **Link the pillar checklists and the AVD product docs, not the CAF AVD scenario.** The Cloud Adoption Framework's enterprise-scale AVD article is deprecated and due to be removed on 2026-10-30; Microsoft points to the Architecture Center and the AVD product docs instead ([deprecation notice](https://learn.microsoft.com/azure/cloud-adoption-framework/scenarios/azure-virtual-desktop/enterprise-scale-landing-zone)). Links under `learn.microsoft.com/azure/well-architected/azure-virtual-desktop/` now redirect into the AVD product docs, so a link there can silently land on a different page.
- **Consume Microsoft's lists before writing rules.** [Azure/review-checklists](https://github.com/Azure/review-checklists) (MIT) has an AVD checklist (`checklists/avd_checklist.en.json`): each item has a category, `waf` pillar, severity, short `id` (`A01.01`), `guid` and Learn `link`, but no Resource Graph query, so the evidence for each item has to be mapped. Cite the short id, not the GUID. [WARA](https://github.com/Azure/Well-Architected-Reliability-Assessment) (MIT, PowerShell Gallery `WARA` 1.0.6) is Reliability only: `Start-WARACollector` (with `-AVD` for AVD resource types) writes JSON, the analyzer an Excel action plan, and the reporter PowerPoint and Excel, which needs Windows with PowerPoint. It needs PowerShell 7.4, Az.Accounts 3.0 and Az.ResourceGraph 1.0.
- **The checklists have stable codes.** Each pillar's design review checklist numbers its items (Reliability RE:01 to RE:10, and SE, CO, OE, PE likewise), so a check can cite the code and the link ([Reliability checklist](https://learn.microsoft.com/azure/well-architected/reliability/checklist)).
- **Microsoft's assessment is a questionnaire.** The Azure Well-Architected Review (about 60 questions, with an Azure Virtual Desktop workload variant) adds Advisor recommendations for one subscription or resource group only, keeps milestones per Learn profile, and exports recommendations as CSV for a backlog ([completing an assessment](https://learn.microsoft.com/azure/well-architected/design-guides/implementing-recommendations)).
- **Advisor refreshes about twice a day**, so a fix shows up in its recommendations hours later; don't dismiss the recommendation by hand to make it go away ([AVD Advisor recommendations](https://learn.microsoft.com/azure/virtual-desktop/azure-advisor-recommendations)).
- **The AVD security baseline is on MCSB v1.0** and may be out of date; Defender for Cloud's regulatory compliance view tracks the current benchmark, so read posture there ([baseline](https://learn.microsoft.com/security/benchmark/azure/baselines/azure-virtual-desktop-security-baseline)).
