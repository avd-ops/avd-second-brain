# 0013. Enforce knowledge capture with a thread closeout, a Stop hook and a PR check, as an AVD pilot

## Context and Problem Statement

Every family KB says decisions and lessons go into the KB, but nothing checked that any did: `kb-validate` checks the shape of what is written, never whether anything was. The family accepted a three-layer fix (the 2ndbrain format, [SPEC section 3](https://github.com/nickprignano/2ndbrain/blob/main/docs/2ndbrain/SPEC.md#3-keeping-a-kb-current)) and asked the AVD repos to pilot it (handoff issue #22). Does this KB adopt it, and how?

## Considered Options

- Adopt all three layers in block mode, as the AVD pilot
- Adopt in warn mode first, like the reference repo
- Keep instructions only

## Decision Outcome

Chosen option: "Adopt all three layers in block mode", because the AVD pilot is the one that tests block mode and repos without a KB of their own (avd-swarm, avd-landing-zone), and none of the layers calls a model.

The design is the 2ndbrain format's ([SPEC section 3](https://github.com/nickprignano/2ndbrain/blob/main/docs/2ndbrain/SPEC.md#3-keeping-a-kb-current)), the source of truth for the design.

In this repo:

- **Thread closeout.** The AVD project's instructions say every thread runs the 2ndbrain closeout before its final reply, and the coordinator doesn't resolve a thread until the closeout is recorded or the owner waives it. Private-layer writes still wait for the owner's yes.
- **Stop hook.** `.claude/settings.json` runs `scripts/kb/capture_check.py hook`, installed unchanged from [2ndbrain](https://github.com/nickprignano/2ndbrain). `docs/knowledge/kb.toml` sets `capture_hook = "block"`.
- **PR check.** `.github/workflows/kb-capture.yml` fails a PR that changes files outside `docs/knowledge/` without a change inside it, unless it carries the `no-kb` label and a `No KB entry: <reason>` line. The family's own automation PRs are exempt.
- **What isn't code here.** `capture_ignore` adds `wiki/**` (generated by `Update-BrainDocs.ps1`) and `knowledge/**` (the brain's engine knowledge, which changes only by a reviewed harvest PR and is itself captured knowledge).
- **Pilot.** Through 2026-10-31, counted from when the hook and the check go live here, reviewed on 2026-11-01. At each checkpoint this project adds one field report to 2ndbrain's `field-reports.yaml`: PRs merged, how many carried a KB change, how many used `no-kb`, and how often the hook blocked.

### Consequences

- Good, because capture no longer depends on remembering an instruction.
- Good, because `no-kb` with a reason makes "nothing to capture" a reviewable choice.
- Bad, because the hook runs only in Claude Code sessions, and a person can still merge past a red check.
- Neutral, because avd-swarm and avd-landing-zone have no KB of their own: their PRs link the lesson here with a `KB: <link>` line.

## More Information

- Guardrails: nothing from a real estate, employer or customer goes into a KB entry, a PR body or a `no-kb` reason.
- The `no-kb` label is created by `kb-freshness`, with the other KB labels.
