# Cost and spend

What AVD and its test sandboxes cost and how spend stays capped: the retail price API, auto shutdown, budgets, and the estimate, run-cost and teardown evidence every sandbox run needs.

## Estimating

- Size in the portal, then validate and price in the preflight ([avd-landing-zone decision 0010](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/decisions/0010-sizing-and-cost.md)).
- The Azure Retail Prices API gains lookalike meters with the same SKU. Match the product name as well as the SKU and meter, and print product, SKU, meter and unit when a match fails ([lesson 0025](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/lessons/0025-retail-price-lookalike-meters.md)).

## Estate FinOps assessment (C11, C19 and C20)

Learned building out the FinOps facts, intake fields, assessment checks (`method.json` v7) and collector extractions across [avd-assess #58](https://github.com/avd-ops/avd-assess/pull/58), [avd-ops #88](https://github.com/avd-ops/avd-ops/pull/88) and [avd-current-state #66](https://github.com/avd-ops/avd-current-state/pull/66) on 2026-11-08:

- **Tag-presence facts without leaking tag names or values.** Azure cost allocation for AVD requires tagging host pools and session hosts (and enabling `cm-resource-parent` tag inheritance when grouping child costs), while `C11` (`avd-current-state-facts/v1`) forbids emitting any customer tag key or value into the snapshot (`tests/Facts.Tests.ps1` puts `'CostCenter'` and `'Finance Team'` in `$script:secrets`). Reducing tag inspection in `Test-CostAllocationTag` to a boolean (`hostPools/*/costAllocationTag`) and an integer count of untagged session hosts (`hostPools/*/sessionHosts/untaggedForCost`) lets `asm-cost-allocation-tags` verify cost attribution posture while keeping the snapshot 100% free of tag strings.
- **Budgets must check `contactGroups` (Action Groups), not email notifications alone.** A `Microsoft.Consumption/budgets` resource with only `contactEmails` sends an email and takes no automated action. Extracting both `budgets.total` and `budgets.withActionGroup` (notifications with `enabled != false` and non-empty `contactGroups`) from `rebuild/rest/budgets.json` lets `asm-cost-budget-action-group` distinguish an actionable budget from an email-only alert without copying budget names, email addresses or action group resource IDs.
- **Azure Advisor cost recommendations live in `advisorresources` and need category plus field/problem filtering.** `Microsoft.Advisor/recommendations` sits in the `advisorresources` Resource Graph table (`lib/AvdRebuild.psm1`, `rebuild/scope.json`), not `resources`. Registering `properties.impactedValue` with `Add-KnownName` prevents resource names in Advisor rows from leaking, while filtering `category == 'Cost'` rows into `unattachedDisks` (`impactedField` matching `disks` or `shortDescription.problem` matching `unattached.*disk`) and `rightSizeVms` (`impactedField` matching `virtualMachines` or `right-size|underutilized`) feeds `asm-cost-no-unattached-disks` and `asm-cost-advisor-rightsize-reviewed` (`informs: ["hostPool.vmSize"]`).
- **Personal host pool deallocation pairs `startVmOnConnect` with `scalingPlan.method` and `sessionHosts.hibernation`.** Enabling `StartVMOnConnect` on a Personal host pool starts stopped VMs when users connect (`asm-personal-start-vm-on-connect`) but never deallocates or hibernates them after sign-out. Joining `microsoft.desktopvirtualization/scalingplans` (`properties.hostPoolReferences` where `scalingPlanEnabled != false`) and VM `properties.additionalCapabilities.hibernationEnabled` into `scalingPlan.method` and `sessionHosts.hibernation` lets `asm-personal-deallocation` verify the stop/hibernate half of the loop.
- **Licensing eligibility (`userLicense`) and compute commitments (`computeCommitments`) belong in `C19` (`intake.schema.json`), not subscription-scoped ARM reads.** Windows 10/11 multi-session rights (`m365-or-windows-enterprise`, `rds-cal`, `per-user-access`) and enrollment- or billing-scoped Reservations and Azure Savings Plans (`reservation`, `savings-plan`, `both`, `none`) sit outside a subscription's `Reader` scope when purchased at the EA/MCA billing scope or in another tenant, so capturing them in `avd-intake/v1` keeps the collector subscription-Reader-only while documenting them on the FinOps dimensions (`cost.licensing`, `cost.commitments`).

## Sandbox RAG and operations memory cost floor

Keeping a tenant second brain and Log Analytics (`WVD*` / AVD Insights) retrieval stack under `$1/month` standing in a sandbox (or `~$10/month` with the standalone `avd-buddy` web app) relies on splitting tabular telemetry from semantic memory and avoiding always-on network and search tiers ([operations red team H9](../../operations-redteam.md), [avd-swarm core-and-adapters section 6](https://github.com/avd-ops/avd-swarm/blob/main/docs/core-and-adapters.md#6-cost-model)):

- **Split retrieval instead of embedding time-series telemetry.** Keep `WVDConnections`, `WVDErrors`, `WVDAgentHealthStatus`, `WVDCheckpoints` and `Perf` in the Log Analytics workspace (Pay-As-You-Go includes a `5 GB/month` free allowance per billing account and `31 days` of free retention; cap sandbox workspaces at `0.5 GB/day`) and query them through fixed KQL catalog IDs (`catalog/kql/`) and the read-only Azure MCP Server (`microsoft/mcp`, `--mode all --read-only --namespace virtualdesktop`). Keep semantic and episodic memory in Git (`Find-BrainKnowledge.ps1` and the v1 deterministic Concierge) or in **Azure Cosmos DB for NoSQL (Serverless)** with native vector indexing at Tier 3 (`$0` idle compute, `~$0.25/GB/month` storage and `~$0.25` per `1M` RUs), rather than **Azure AI Search**, which has no serverless tier (`~$73/month` standing for Basic, while Free `F0` lacks managed identities and private links and stops at `50 MB`).
- **Use scale-to-zero compute and free-tier guardrails.** Host the Agent API, deterministic Concierge and Azure MCP Server on **Azure Container Apps Consumption** (`0.5 vCPU`, `1 GiB`, `minReplicas: 0`, inside the monthly free grant of `180,000 vCPU-seconds`, `360,000 GiB-seconds` and `2M` requests), **Azure AI Content Safety `F0`** for Prompt Shields (`5,000` free text records a month, which refuses calls past quota instead of billing), **Azure Logic Apps Consumption** for the kill switch (fractions of a cent per trip or drill), and **Standard LRS Blob and Table Storage** (shared keys off) for `C11` facts, immutable evidence and the single-partition token spend counter (`~$0.05/month`). In a sandbox, serving the chat UI from the scale-to-zero Container App with built-in Entra Easy Auth (or querying from Cloud Shell / GitHub Actions) avoids the `~$9/month` fixed charge of **Azure Static Web Apps Standard** until `avd-buddy`'s custom federated Entra sign-in is needed.
- **Avoid standing Private Endpoint charges in a sandbox.** Each Azure Private Endpoint bills `~$0.01/hour` (`~$7.30/month`) plus `~$0.50/month` per Private DNS Zone, so placing Private Endpoints in front of Storage, Cosmos DB, Key Vault and Log Analytics adds `~$30 to $38/month` in idle network charges before a single query runs. For a nonproduction sandbox, keep `publicNetworkAccess: Enabled` with **Entra-only authentication (`disableLocalAuth: true`, shared key access disabled)** and IP or service-tag firewall rules so standing network cost stays `$0/month`.
- **Evaluate scheduled KQL checks in code before calling a model.** Scheduled and alert-triggered runbooks evaluate KQL measures deterministically in code first (`expect: sessionHosts.unhealthy == 0`) and call an LLM only when a threshold fails (`onFail: investigate`), keeping token spend at `$0` while the sandbox estate is healthy ([agents KB](../agents/README.md)).

## Capping

- One auto-shutdown runbook, started both by a schedule and by the budget ([avd-landing-zone decision 0011](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/decisions/0011-auto-shutdown.md)). *Unverified:* no lesson yet records the budget trigger in a real run.
- The landing zone's budget lives and dies with it: `Remove-AvdDemo.ps1 -IncludeLandingZone` deletes `budget-<prefix>-<environment>`, so a torn-down sandbox subscription has no spend alert at all ([Remove-AvdDemo.ps1](https://github.com/avd-ops/avd-landing-zone/blob/master/scripts/ops/Remove-AvdDemo.ps1)). Give a sandbox subscription a standing budget of its own that no teardown touches, and have the daily spend check flag a subscription without one.

## Sandbox runs

- Every sandbox run needs a cost estimate first, run-cost evidence, teardown evidence and a monthly reconciliation ([avd-swarm spend process](https://github.com/avd-ops/avd-swarm/blob/main/docs/spend.md)).
- A public lab must carry its own spend guard: a run that opens and closes through a private repo can't be run by anyone else. avd-swarm's [spend guard](https://github.com/avd-ops/avd-swarm/blob/main/spend/README.md) refuses before any deploy (unpriced line, over the run cap, month to date plus estimate over the monthly cap, a second open run) and keeps its records outside the repo.
- Azure has no hard stop on spend: a budget only alerts. Enforce caps before the run opens and check the run's due time on every resume; cap model tokens per call in the agent service, with the provider's workspace limit as the backstop.
- Cost Management lags the spend, so month to date for a cap check is billed cost plus the estimates of runs not yet settled, and a run's actual cost is settled no sooner than three days after teardown. Read it by the run's own resource group and day, so charges after the close day show up as a tail. *Unverified:* no settled run recorded yet.
- The sandbox run method (spend gate, batches, approvals, teardown evidence) ships with the landing zone and runs from Azure Cloud Shell alone ([avd-landing-zone decision 0020](https://github.com/avd-ops/avd-landing-zone/blob/master/build/decisions/0020-sandbox-runs-in-the-package.md), [operator guide](https://github.com/avd-ops/avd-landing-zone/blob/master/docs/sandbox-runs.md)). Cloud Shell ends idle sessions after about 20 minutes and its home folder is not a durable copy, so records live in the run store's `records` container, written with conditional writes (If-Match on the last ETag seen, If-None-Match for a new file), and a group's first results write is its claim: a second shell starting the same group gets a conflict before spending.
- A run ID made from the start minute (`yyyyMMdd-HHmm-<kind>`) collides when two runs start in the same minute, which a resume or a scripted batch makes likely, and the second record overwrites the first. Add a letter after the minute when the ID is taken, and order runs by their start time, not file name: PowerShell's culture-aware sort ignores hyphens, so `1705-liquidware` and `1705b-liquidware` sort the wrong way round. Found by the landing zone's SandboxBatch offline scenario, before a real run lost a record.
- A group runs once per approval: a second start would spend its estimate twice. Resuming replays finished steps from the results and reruns the interrupted one, so item steps must be safe to run twice.
- Check the sandbox before a group spends, read-only and before its claim, so a failure costs nothing and the same command runs again once fixed ([Test-AvdSandboxHealth.ps1](https://github.com/avd-ops/avd-landing-zone/blob/master/scripts/ops/Test-AvdSandboxHealth.ps1)). The leftover a new run can't get past by itself is an Entra device named exactly like a host (`<prefix><e>sh-<n>`, or a blue/green generation's ten-character prefix plus `a` or `b`): a new host of that name can't join. Call a device stale only when no VM in any subscription the identity can read carries the name (Resource Graph with no subscription list, by VM name and computer name), and report it rather than delete it. `Invoke-AzRestMethod -Uri https://graph.microsoft.com/...` reads Graph on the same Cloud Shell sign-in, with no Graph module or second sign-in.
- An unattended teardown that runs as an app identity (GitHub Actions with a federated credential) needs more than Contributor. Deleting the landing zone's policy assignments needs Resource Policy Contributor. Deleting the session hosts' Entra devices needs the Graph app role `Device.ReadWrite.All`, and the cleanup has to use the app's own Graph token (`Get-AzAccessToken -ResourceTypeName MSGraph`, then `Connect-MgGraph -AccessToken`), because there is no user to sign in. Without it, the next run's host fails to join with `0x801c0083` ([avd-landing-zone lesson 0033](https://github.com/avd-ops/avd-landing-zone/blob/master/build/lessons/0033-app-identity-graph-cleanup.md)). Found on the first unattended round trips, 2026-10-21.
- Records that several jobs commit to one git branch need a rebase-and-retry push loop. A plain `git push` after another job's commit fails with `fetch first`, and the run's results and spend record were lost that way once. Pull with `--rebase` and push again, a few times with a short wait, then fail loudly.
- Keep a sandbox's queue beside its run records (in the operator's run-store repository), as one item file per waiting run plus an index generated from them that people and agents read first. A fresh Cloud Shell or any coding agent can read a file with no GitHub CLI sign-in, which issues don't allow, and git keeps the history. Always check the run store's copy of the queue before assuming a run left no record.
