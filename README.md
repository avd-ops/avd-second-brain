# avd-second-brain

Part of [avd-ops](https://avd-ops.dev/), the open toolkit for Azure Virtual Desktop.

The estate brain for **Azure Virtual Desktop**: it understands why each AVD environment is built and performs the way it does, and keeps its living RAID log. It records each environment's use cases and the decisions made building, configuring, expanding, contracting and fixing it, from its birth (decision 0020, [PR #45](https://github.com/nickprignano/avd-second-brain/pull/45)). It also tracks the risks, assumptions, issues, dependencies and actions that are open on it. It sits on top of the foundation (avd-assess, avd-current-state, avd-landing-zone), which works without it, and [avd-swarm](https://github.com/nickprignano/avd-swarm) acts on what it proposes. Scope: [decision 0024](docs/knowledge/decisions/0024-the-brain-is-the-estate-brain.md).

## Quick start

PowerShell 7.4 (Azure Cloud Shell has it). No modules.

```powershell
git clone https://github.com/nickprignano/avd-second-brain.git
Set-Location avd-second-brain

# Ask the brain, across this repo and the connected repos
./scripts/Sync-BrainSources.ps1                                        # check out the connected repos (.sources/)
./scripts/Find-BrainKnowledge.ps1 'fslogix kerberos'                   # search, with commit-pinned citations
./scripts/Find-BrainKnowledge.ps1 -App 'Skype for Business 2016'       # resolve an inventory app name
./scripts/Find-BrainKnowledge.ps1 -Calibration                         # sizing factors per tier and VM family

# A customer's estate vault, from avd-current-state packages (in their own private repo)
./vault/avd_second_brain.ps1 -BrainPath ../contoso-avd-brain -Init
./vault/avd_second_brain.ps1 -BrainPath ../contoso-avd-brain -PackagePath ../avd-current-state/avd-current-state-20261015T091500
./scripts/Get-VaultHarvest.ps1 -VaultPath ../contoso-avd-brain         # what may cross into the knowledge base

# Measured utilization from the factory's verify stage or the landing zone
./scripts/Import-SizingEvidence.ps1 -EvidencePath ./sizing-evidence.json

# Before every PR that touches knowledge/
./scripts/Test-Knowledge.ps1                                           # RESULT PASS, or what to fix

# Docs consistency (docs/docs-spec.md): check, then regenerate what the check says is stale
./scripts/Test-DocConsistency.ps1
./scripts/Update-BrainDocs.ps1
```

## Rules that keep it trustworthy

- **Tenant data stays with the tenant.** Vaults live in the customer's private repo; the knowledge base holds only generalized facts, and a guard (`scripts/Test-Knowledge.ps1`, in CI) fails on customer names, addresses, IDs, LOB apps and engagement trails in the public scope.
- **Models propose, people approve.** Knowledge changes only by a PR a person merges. A model never sets a verdict, a rule or a plan on its own.
- **The guardrails apply to everyone** ([docs/guardrails.md](docs/guardrails.md); AI assistants also read [AGENTS.md](AGENTS.md)): nothing in the repo identifies a tenant, customer or employer; secrets never go through chat, the repo or the knowledge base; changes land as pull requests and nothing touches a real environment without the owner's yes; code from unlicensed repos is reference only; Azure-native, GitHub and open-source tooling first, with no HCL (Terraform, Packer) in any AVD repo; everything runs from Azure Cloud Shell; nothing deletes the last copy of data ([decision 0016](docs/knowledge/decisions/0016-never-delete-the-last-copy.md)).
- **Every number traces to evidence.** Rules carry a history with a reason per change; catalog verdicts cite a document, a pilot or an engagement; calibration factors are computed from observations when read.
